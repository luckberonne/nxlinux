# How tightly nxnative's NVN layer is tied to Metal

Measured on nxnative `dm/gfx/nvn` by trial-compiling `hle_nvn.c` on this machine with the Mario Kart 8 profile header
(generated by `dm/games/game.py header`) and empty stand-ins for the Apple headers.

## hle_nvn.c (2578 lines): portable, with a small Apple surface
148 error lines, 52 distinct source lines, in 17 places. **None is a graphics API call.** They are:

| Kind | Where | Replacement |
|---|---|---|
| `CommonCrypto` SHA-256 | `keys_hash` (program key = first 8 bytes of SHA-256 of control + code, the same key the offline shader tools use) | any SHA-256 |
| `CFDictionary` pointer -> keys map | `pk_get`, `pk_drop` | a small hash map |
| `vm_remap` | `vpool_map` (sparse / virtual pools: one page range visible at two addresses) | `mmap` of a memfd at a second address, which needs the guest window to be a shared memfd mapping, not `MAP_PRIVATE` |
| `mach_timebase_info`, `clock_gettime_nsec_np` | timing helpers | `clock_gettime` |
| `task_info`, `thread_info`, `mach_task_self` | `tsummary`, `power_line`, `thr_sys_ns`, `fstep_cpu_slowed`, `dump_frame`: statistics and power reports | `/proc/self`, or drop |
| `THREAD_TIME_CONSTRAINT_POLICY`, QoS classes | `set_time_constraint_comp`, `sleep_until_ns`, `rt_comp_tick`: real-time thread hints | `sched_setscheduler` or drop |

The host header (`hle.h`) registers functions in Mach-O sections (`__DATA,swhle`); ELF does the same with a plain section
name and `__start_` / `__stop_` symbols.

## The Metal interface hle_nvn.c calls: 82 functions, 33 of them core
Core (needed for a first picture): `mtl_pool_add/del`, `mtl_addr`, `mtl_alias_drop_pool`, `mtl_sub_begin/commit/index`,
`mtl_queue_activate/forget`, `mtl_exec`, `mtl_exec_rest`, `mtl_last_fence`, `mtl_finish`, `mtl_drain`, `mtl_reg_tex/samp/image`,
`mtl_tex_init/release/cpu_written/gpu_owned`, `mtl_read_texels`, `mtl_prog_release`, `mtl_set_tex_pool_n`, `mtl_set_depth_zero`,
`mtl_set_origin_lower_left`, `mtl_set_queue_origin_lower_left`, `mtl_set_frame`, `mtl_present`, `mtl_present_wait`,
`mtl_has_window`, `mtl_xv_window_tex`, `mtl_ds_omit`.
The other 49 are statistics, frame-pacing and tuning (`*_stats`, `link_*`, `pkg_*`, `ub*`, `fps_target`, ...): stubs at first.

## nvn_mtl.m (11203 lines, 425 functions): what to write, and what to leave out
The record format is API-neutral: the game's NVN calls become ~45 ops (`OP_SET_RT`, `OP_DRAW`, `OP_BIND_*`, `OP_COPY_*`, ...) in
`nvn_obj.h`, replayed at submit time. A Vulkan replayer implements those ops. The largest pieces in the Metal one are
`draw_` (322 lines), `encode_args_` (236, the argument-buffer fill), `rp_begin_ex_` (199, render pass setup), `mtl_exec` (147),
pipeline building (`pso_*`, ~400), texture upload and deswizzle (`tex_*`, `pkg_upload_`, `up_*`, ~400) and presentation.
A large share is optimisation that has no place in a first version: TBDR pass merging (`fuse_try`, `defer_try`, `hoist_try`),
the geometry-shader mesh emulation, indirect-draw index conversion (`ixc_run`), MetalFX, frame snapshots and capture.

Estimate for a first working Vulkan replayer (menus, then a race): roughly 4-6 thousand lines of C, written against the
`nvn_metal_mapping.md` table, which maps almost one-to-one.

## Order
1. `hle.h` / `dm.h` stand-ins and the Apple replacements above, so `hle_nvn.c` compiles and links (no GPU yet).
2. `nvn_vk.c` with the 33 core entry points (the rest as stubs): pools, addresses, sync, textures from the existing deswizzle code.
3. Op replay: render targets, clears, state, draw, then bindings (the argument fill from the shader reflection).
4. Shaders: SPIR-V from `dmsh_xlate`, reflection from SPIR-V instead of MSL text.
5. Presentation with SDL3.

## Status: hle_nvn.c runs on Linux behind a null GPU
`hle_nvn.c`, `nvn_dirty.c`, `nvn_capture.c`, `nvn_tex.c` and the deswizzle code build and link on Linux (target `nxnvn`; `nvn_link_check`
links every object and fails on any unresolved symbol). Its constructor runs: 537 NVN names, 427 implemented (413 with semantics,
14 empty), the other 110 report in red. What replaced the Apple parts:
- `src/gfx/nvn/nvn_platform.h`: clocks, resident memory from /proc, a safe pointer read, Mach calls that report failure.
- `src/host/sha256.c` for the program keys (tested against FIPS vectors and `sha256sum`), a pointer map instead of CFDictionary.
- `src/gfx/nvn/nvn_null.c`: the 70 Metal-layer functions. Pools and addresses are real, submissions complete at once, nothing is drawn.
- NVN function thunks are svc stubs in the guest window (`nvn_thunk_for`), reaching the implementation through `hle_call`.
- `src/host/faults.c`: the SIGSEGV dispatch dirty tracking needs, re-installed on top of dynarmic's handler after each Jit is made.
Left out for now: `vm_remap` (virtual pools need a shared guest window), LZFSE capture compression, power and QoS statistics.

## Verified end to end from guest code (tests/guest/nvn_smoke.c, tests/test_nvn_guest.cpp)
An aarch64 program built against the real `nvn.h` runs on the emulated CPU and does what a game does first: `nvnBootstrapLoader`, device
(API 55.15 from the profile, pool page size 65536 and queue command memory minimum 65536, the Tegra X1 values in `g_devinfo`), a memory
pool over its own `.bss` (`nvnMemoryPoolMap` returns that address), two buffers in the pool whose GPU addresses equal their CPU addresses,
a queue, a command buffer (viewport, scissor, buffer copy), `EndRecording`, `QueueSubmitCommands`, a fence and `SyncWait`, then teardown.
Path: guest code -> svc stub -> `hle_call` -> the NVN function in `hle_nvn.c` -> the null GPU. No `[RED]` line, no unimplemented import.

## Vulkan backend, first part (src/gfx/nvn/nvn_vk.c)
Replaces the pool, address, fence and in-submission copy/fill entry points of the null GPU; `nvn_null.c` keeps presentation, pacing,
statistics and the command replay (`mtl_exec`) until those are written. Set `NX_NULL_GPU=1` to run without opening a Vulkan device.
- **Pools**: a pool is guest memory imported with `VK_EXT_external_memory_host` and bound to one buffer; `mtl_addr` resolves an address to
  (buffer, offset) by interval lookup. The range is widened to the import alignment (4096); a pool that cannot be imported is reported in red.
- **Submissions**: one command buffer between `mtl_sub_begin` and `mtl_sub_commit`, submitted with a timeline semaphore signal. The fence
  value is the timeline value, `mtl_wait` is `vkWaitSemaphores`, so a fence completes only when the GPU has reached it. Command buffers are
  recycled once the timeline passes them.
- **Operations**: `mtl_sub_copy` and `mtl_sub_fill` record `vkCmdCopyBuffer` / `vkCmdFillBuffer` with a transfer barrier after each, so
  dependent operations in one submission see each other's writes.
- Tests: `test_nvn_vk_pool` (pools, lookups, copies between pools, fill -> copy -> copy, fences, 200 submissions, pool removal and re-add) and
  `test_nvn_guest` (the guest program of the previous section, now on the GPU).
Not yet: events and counters written after completion (`mtl_sub_event`, `mtl_sub_counter`), pools larger than `maxBufferSize`, virtual pools.

## Command replay, first part (src/gfx/nvn/nvn_replay.c)
`mtl_exec` walks the record lists the way nxnative's does (END, JUMP, CALL with return) and executes, on the Vulkan backend:
`OP_COPY_B2B`, `OP_CLEAR_BUF`, `OP_UPDATE_UB` (inline data: `vkCmdUpdateBuffer` when it fits, otherwise a staging buffer kept until the
submission completes), `OP_BARRIER` (a full memory barrier covers every combination of the game's bits), `OP_SIGNAL_EVENT`,
`OP_REPORT_COUNTER` and `OP_FENCE_SYNC`. Everything that draws is accepted and announced once (`replay: OP_X is recorded but not executed yet`).
- **Effects of completion** (event writes and adds, counter reports) are queued with the submission and performed after the GPU has completed
  it, in submission order, by a completion thread. A waiter on a fence drains the queue up to that fence before it returns, so whoever sees a
  fence complete has also seen its effects: events never lag behind their sync objects. A counter report is `{counter, timestamp}`, the
  timestamp in 614.4 MHz ticks of the guest clock (`nvn_timestamp.h`).
- **Checked** by `test_nvn_guest` (a guest records a fill, a copy, a barrier, a copy of that copy, an inline uniform update whose source it
  then overwrites, a timestamp report, two event signals and a fence; the memory is verified after the fence, and the event reads 42: written
  7, then 35 added). A control run with `NX_NULL_GPU=1` fails exactly the data checks, so the test does discriminate. `test_nvn_vk_pool` covers
  the order of effects over many submissions and hand-built lists (CALL, JUMP, the staging path with an odd size and offset).
Not yet: the samples-passed counter (needs occlusion queries), conditional rendering, and every op that draws.

## Textures on Vulkan (src/gfx/nvn/nvn_tex_vk.c)
Each NVN texture gets a `VkImage` (mip levels, array layers, cube and 3D; format from the `nvn_fmt_to_vk` table, usage from the format's features).
Images stay in `VK_IMAGE_LAYOUT_GENERAL`: one layout serves transfers, sampling, storage and attachments, so no transitions are tracked.
- **Where the truth is, per subresource** (a mip level of one array layer). The storage in the pool (block-linear) is the truth for packaged
  textures and for what the CPU writes; the image is a cache of it and a subresource marked DIRTY is de-swizzled (`nvn_deswizzle`) and uploaded
  the next time the GPU uses it. A buffer->texture copy makes the image the truth for what it covers (GPU). A CPU read of a subresource the GPU did
  not write de-swizzles the storage directly; of one it did, reads the image back after the submitted work has completed.
  Per subresource, because `hle_nvn.c` knows the level and layers a `WriteTexels` touches (`mtl_tex_cpu_written_sub`): a whole-texture flag
  would re-upload the storage over what the GPU wrote to other levels, which nxnative avoids by mirroring every copy back into the storage.
- **Copies**: `OP_COPY_B2T` / `OP_COPY_T2B` with the row and image strides of `OP_COPY_STRIDE` (a padded stride works), regions inside a level,
  edge blocks of compressed formats. Not yet: copies between textures, texture clears, the mirror into the storage that nxnative keeps for the
  CPU's benefit, depth-stencil upload, multisampled textures, formats Vulkan lacks here (ASTC; the 3-component formats need expanding).
- **Released textures** are destroyed once the timeline passes every submission that may mention them.
- **Thread safety**: the queue and the command pool are externally synchronised, so submit, one-shot readbacks and command buffer recycling
  share a lock.
- Found on the way: a barrier that transitions only layer 0 left array layers and cube faces in `UNDEFINED`; RADV tolerated it and the
  validation layer reported it. `test_nvn_vk_tex` (2D with mips, BC1, BC7 with edge blocks, 2D array, 3D, cube, padded strides, both `ReadTexels`
  paths, the CPU rewriting one level of a GPU-written texture) and the texture section of `test_nvn_guest` (through the real NVN API) cover it.

## Render targets and clears (nvn_replay.c, nvn_tex_vk.c)
`OP_SET_RT` keeps the serials and views of the targets (the textures in a record are snapshots made at record time); `OP_SCISSOR` the scissor.
`OP_CLEAR_COLOR` and `OP_CLEAR_DS` run as a rendering pass of their own whose load operation is the clear, with the scissor as the render area, so
the area limits what is cleared. One path covers the scissor, a view that reinterprets the format (an RGBA8_SRGB view of an RGBA8 texture: the
linear clear value is stored encoded), one mip level, a range of array layers, integer targets (the game records the value as a float; it is
converted to the attachment's integer type) and depth and stencil. nxnative defers a clear into the next pass's load action because that is cheaper
on a tile-based GPU; a desktop GPU gains nothing from it, so the clear is done where it is recorded.
Not yet: a colour clear with a channel mask (`mask != 0xF`) and a stencil clear with a partial mask (Vulkan's load operation cannot mask; nxnative
draws a triangle, which needs the draw path), 3D textures as targets, multisampled targets. The first two are announced in red once and leave the
target alone rather than guess.
Attachment views carry an explicit `VkImageViewUsageCreateInfo`: without it an sRGB view inherited `STORAGE` from the image, which the format
does not support (reported by the validation layer).
Checked by `test_nvn_vk_tex` (whole, scissored, one level through a view, sRGB view, R32_UINT, array layers, depth, scissored depth, stencil, a
masked clear that must change nothing) and by the guest through `SetRenderTargets` / `ClearColor` / `SetScissor` in `test_nvn_guest`.

## Draws (src/gfx/nvn/nvn_draw_vk.c, nvn_shader_vk.c)
The replay accumulates the state records (`OP_BIND_PROGRAM/STATE/VATTR/VSTREAM/VBUF/UBO`, viewports, depth range, stencil, polygon offset, blend colour,
primitive restart, rasteriser discard) and a draw (`OP_DRAW`, `OP_DRAW_IDX`) turns them into Vulkan:
- **Programs and shaders.** `hle_nvn.c` already computes each shader's 8-byte key; `nvn_prog_keys` exposes a program's keys. A registry
  (`nvn_vk_shader_register`) maps a key to SPIR-V, its stage and its bindings. The offline chain (`dmsh_xlate`) will fill it; the tests register hand-written
  SPIR-V for fake shaders whose control and code bytes they choose, and compute the key the way `keys_hash` does.
- **Pipelines** are built from the whole state, already in Vulkan terms (blend factors and operations, depth and stencil functions, cull and winding, polygon
  mode, vertex layout, attachment formats), and cached by a `memcmp` of that key. Viewport, scissor, depth bias, blend constants and the stencil masks and
  reference are dynamic. The blend, depth-stencil, polygon, colour and channel-mask enums of NVN map onto Vulkan's by tables (the depth, stencil and compare
  enums happen to be the same order shifted by one).
- **The render pass** opens at the first draw with `LOAD` on every attachment and stays open until something else needs the command buffer:
  `nvn_vk_cmd()` ends it, so every copy, fill, clear and barrier gets that for free. A change of render targets reopens it.
- **Conventions of NVN's GL heritage**, checked by the test against pixels: depth through `VK_EXT_depth_clip_control` (negativeOneToOne), so the clip volume is -w..w
  as in NVN and no shader needs a depth variant (a triangle at NDC z = -0.5 stores exactly 0.25); a lower-left window origin keeps the viewport unflipped and
  inverts the front face (Vulkan names winding as seen with y down), an upper-left origin flips the viewport and keeps it.
- **Uniform buffers** are pushed with `VK_KHR_push_descriptor`, one binding per (shader, uniform slot) as the registry says; an unbound slot reads zeros.
- Found on the way: `SetViewport` records only x, y, w, h, so the record's near and far are zero: the depth range is `SetDepthRange`'s, 0..1 by default.
Checked by `test_nvn_draw` through the real NVN API from guest code: default state, culling in both senses, blending, depth test and stored depth, channel mask,
uniform buffers in both stages, indexed draws (the index order is what the culling sees), and a program with no registered shaders (the draw is skipped, announced
in red once, the frame goes on). The same test on the null GPU fails every drawing check.
Not yet: textures and samplers in shaders (the bindless arrays are tested apart), storage buffers, the driver constant segments c0 and c2, the translated shader
library and its JSON reflection, geometry and tessellation stages, compute, indirect and multi-draws, line loops / quads / polygons and 8-bit indices (they need
an index list built), several viewports, multisampling, logic ops, alpha test, transform feedback, conditional rendering, clears with a channel mask.

## Translated shaders reach the draw path

The Maxwell -> SPIR-V translator (Ryujinx's, with nxnative's patches) is vendored in `third_party/ryujinx` and driven by `tools/dmsh_xlate` (.NET; `dotnet build` is the only
requirement, and CMake builds it when `dotnet` exists). Its output, `<key>.spv` plus `<key>.res.json`, is packed by `tools/shader_pack.py` into one library (`NXSL`) that
`nvn_vk_shader_load_library()` registers under the same 8-byte keys `hle_nvn.c` computes. Each entry carries a `needs` mask: what the shader reads that the draw path cannot
supply yet (driver segments c0/c1/c2, storage buffers, textures, images, geometry helper buffers). A draw whose shader needs any of them is skipped with a red line that names
what is missing, instead of running wrong. Plain uniform buffers (c[3+n]) are already bindings.

`tools/maxwell_asm.py` assembles the few instructions the tests need (MOV32I, EXIT, the SPH header, the scheduling words). The ninth stage of `tests/guest/nvn_draw.c`
draws with a fragment shader made that way and expects constant orange; `tests/test_maxwell_xlate.py` checks the chain on its own.

The translator declares the capabilities of its whole instruction set in every module (Float64, ImageGatherExtended, fragment shader interlock), so the device now enables
those features; a GPU without them cannot take translated shaders. RADV has all three. The validation layers caught this: the module was accepted but undeclared-feature use was flagged.

Stage ten of the draw test runs a whole translated pair: `maxwell_asm.vertex_passthrough()` (ALD of attribute 0 as the position and 1 as the colour, AST to the position and
to generic output 0) and `fragment_varying()` (IPA of generic input 0 into target 0). Two things came out of the validation layers: the translator's SPIR-V uses
DrawParameters (the device now enables `shaderDrawParameters`), and its `gl_PerVertex` block carried ClipDistance[8] plus CullDistance[1], over the 8 that
`maxCombinedClipAndCullDistances` allows on RADV. Maxwell has no cull distances, so the vendored translator (`CodeGen/Spirv/Declarations.cs`) no longer declares that member.

Stage eleven: `maxwell_asm.vertex_shifted()` reads the vertex uniform buffer with LDC from constant buffer 3 (NVN uniform slot 0) and adds it to the position, as stage F does with
GLSL. The translator gives the buffer binding 1; binding 0 is its `support_buffer` (render scale, viewport size, y negate), which these shaders declare but never read.
A shader that does read it (fragment coordinates, y flipped framebuffers) needs that buffer bound: not done yet, and `needs` does not flag it.

## Sampled textures

Stage twelve of the draw test samples a texture from a translated fragment shader (`maxwell_asm.fragment_textured()`: IPA of the coordinates, then TEX). What it took:
- `nvn_desc_vk.c` keeps what the game registers into its pools by the host-table id (`mtl_reg_tex`: the texture's serial, the view and swizzle it asked for; `mtl_reg_samp`: the
  sampler state) and turns a bound handle (texture id | sampler id << 20) into a `VkDescriptorImageInfo`. Samplers are made lazily from the NVN state (filters, wrap modes,
  compare, anisotropy, LOD range; plain NEAREST / LINEAR clamp the LOD to the base level, as GL does; custom border colours are approximated by the three Vulkan presets).
- `nvn_vk_tex_sampled` (nvn_tex_vk.c) makes the sampling view: the registered levels, layers, format and swizzle on the texture's own target, cached per texture. A dirty texture is
  filled from its storage first, which ends the render pass, so `prepare()` resolves textures before it opens the pass.
- The replay stores `OP_BIND_TEX` / `OP_BIND_TEX1` handles per stage and slot (a deferred bind is read when it runs); a shader's texture binding names its c[2] slot.
- The shader library is version 2: a binding carries `aux`, the translator's SamplerType, so a draw refuses a texture of another type. `shader_pack.py` turns plain 2D textures read
  through a combined handle into bindings; separate textures, arrays, cube maps, shadow samplers and bindless handles still set `needs`.
A texture slot that is bound to an unregistered id skips the draw with a red line (nxnative reads zeros there; a dummy texture is still to do).

## The draw guest as an NSO from a synthetic NSP

`tests/test_boot_synth.py` (ctest `boot_synth`) carries the whole draw test through the real load path: the guest is linked with `tools/synth_guest.ld` and `tools/synth_mod0.S`
as an NSO, `tools/synth_nsp.py` packs it into an NSP with throwaway keys, `work/nx_extract` extracts the ExeFS, `tools/nso.py` makes the memory image, and `test_nvn_draw`
(with `NX_IMG_BSS` set) maps it through its MOD0, relocates it and runs all stages on the JIT. The linker script used to pin the data segment at 0x2000, which only fits a guest
with under 8 KiB of text; the MOD0 pointer is now a link-time difference and the segment follows the read-only data. Skips itself without clang, the `.venv` with cryptography
or a built `work/nx_extract`.

## The driver's constant segments and the support buffer

A translated shader no longer sets `needs` for c[0] and c[2]: the library carries them as bindings (kinds 4 and 5), as it does the translator's support buffer (kind 3, only when
the module actually loads through it: `shader_pack.support_binding` reads the SPIR-V). The draw path builds each one per draw into a host-visible buffer that the submission
frees when it completes (`driver_buffer` in nvn_draw_vk.c):
- **c[0]** (DMSH_DRV_SIZE bytes): the point size limit (the device's, capped at 64) at 0x610 and the draw's base instance at 0x644. The storage buffer tables stay zero: shaders that use
  storage buffers still set `needs`.
- **c[2]**: the handle bound to each combined texture slot (0x20 + 8 r) and each separate one (0x168 + 8 r). Separate samplers (0x568) are not recorded yet.
- **support buffer** (1392 bytes, std140 as the translator declares it): viewport inverse and size from the current viewport, every render scale 1.0, no alpha test, no BGRA swap.
Stage thirteen of the draw test reads all three from one machine-code fragment shader and checks the colour it writes. Still missing: the shader's own constant segment c[1],
storage buffers, images, geometry helpers.

An unregistered texture or sampler id now reads as an empty slot, as on the hardware: a 1x1 texture of zeros of the type the shader samples (1D, 2D, 3D, cube, and arrays of them; made on first
use, cleared to zero) through a nearest-filter sampler. Shadow samplers have no stand-in (a draw that needs one is skipped). The library accepts those types for combined textures; multisampled
ones and buffer textures still set `needs`. Stage fourteen of the draw test checks the zeros.

## Storage buffers

A shader that reads or writes global memory through an address kept in the driver segment c[0] (the NVN convention: the stage's table at 0x110 vertex, 0x310 compute, 0x410 geometry,
0x510 pixel, 0x10 bytes per slot, address then size) comes out of the translator with a storage buffer binding. The reflection gives the table slot (`slot`) and where the address
is read (`cb_slot`, `cb_offset` in words); `shader_pack.py` accepts the ones inside the stage's table as kind 6 bindings (`reg` = the slot) and leaves `needs` set for an address kept in
a game uniform buffer. The binding of c[0] itself is not in the reflection when only the storage conversion reads it, so the packer now takes every constant-buffer binding from the
module's own uniform blocks (`<stage>_c<n>`). The replay keeps the storage buffers bound per stage and slot (`OP_BIND_SSBO`); a draw binds each as a storage buffer descriptor (an unbound slot
reads zeros) and writes the same addresses and sizes into the c[0] table. Stage fifteen of the draw test loads a float that way.
The shader's own constant segment c[1] (the end of its code area: control +0x700 is its offset, +0x704 the area's length; the bytes before the control section are only the same when the two were allocated together, and Mario Kart 8 Deluxe's were not) is captured with the shader and stored in the library (NXSL version 3), and a draw binds
it as a uniform buffer (binding kind 7). Not done yet: images, the geometry helpers, separate textures and samplers, multisampled and buffer textures, and indexing storage buffers by a game-computed address.

## Presentation

`nvn_present_vk.c` implements `mtl_present` the plain way: the presented texture (RGBA8 or BGRA8, the crop of the window or the vi layer; an all-zero crop means the whole texture)
is read back to the host after the GPU finished it, converted to RGBA8, and handed to a sink. The default sink keeps the last frame in memory (`nvn_present_last`, `nvn_present_count`),
which is what the tests read: stage sixteen of the draw test presents a frame through a two-texture window and the host checks its pixels. `NX_PRESENT=sdl` (when SDL3 was found at
configure time) starts a thread that owns an SDL window with a vsynced renderer and shows the frames; closing the window sets `nvn_present_quit_requested`. Tickets are completed when
the sink has shown the frame, which is what `mtl_present_wait` (called from the window's acquire) waits for. Checked here with `SDL_VIDEO_DRIVER=offscreen`; a visible window has not been looked at yet.
The readback of a 1080p frame is about 8 MB per present; a swapchain with a GPU blit replaces it when the cost shows.
