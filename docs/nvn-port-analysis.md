# How tightly nxnative's NVN layer is tied to Metal

Measured on nxnative `dm/gfx/nvn` by trial-compiling `hle_nvn.c` on this machine with the Mario Kart 8 profile header
(generated by `dm/games/game.py header`) and empty stand-ins for the Apple headers.

## hle_nvn.c (2578 lines): portable, with a small Apple surface
148 error lines, 52 distinct source lines, in 17 places. **None is a graphics API call.** They are:

| Kind | Where | Replacement |
|---|---|---|
| `CommonCrypto` SHA-256 | `keys_hash` (program key = first 8 bytes of SHA-256 of control + code, the same key the offline shader tools use) | any SHA-256 |
| `CFDictionary` pointer -> keys map | `pk_get`, `pk_drop` | a small hash map |
| `vm_remap` | `vpool_map` (sparse / virtual pools: one page range visible at two addresses) | `mmap` of a memfd at a second address, which needs the guest window to be a shared memfd mapping, not `MAP_PRIVATE` |
| `mach_timebase_info`, `clock_gettime_nsec_np` | timing helpers | `clock_gettime` |
| `task_info`, `thread_info`, `mach_task_self` | `tsummary`, `power_line`, `thr_sys_ns`, `fstep_cpu_slowed`, `dump_frame`: statistics and power reports | `/proc/self`, or drop |
| `THREAD_TIME_CONSTRAINT_POLICY`, QoS classes | `set_time_constraint_comp`, `sleep_until_ns`, `rt_comp_tick`: real-time thread hints | `sched_setscheduler` or drop |

The host header (`hle.h`) registers functions in Mach-O sections (`__DATA,swhle`); ELF does the same with a plain section
name and `__start_` / `__stop_` symbols.

## The Metal interface hle_nvn.c calls: 82 functions, 33 of them core
Core (needed for a first picture): `mtl_pool_add/del`, `mtl_addr`, `mtl_alias_drop_pool`, `mtl_sub_begin/commit/index`,
`mtl_queue_activate/forget`, `mtl_exec`, `mtl_exec_rest`, `mtl_last_fence`, `mtl_finish`, `mtl_drain`, `mtl_reg_tex/samp/image`,
`mtl_tex_init/release/cpu_written/gpu_owned`, `mtl_read_texels`, `mtl_prog_release`, `mtl_set_tex_pool_n`, `mtl_set_depth_zero`,
`mtl_set_origin_lower_left`, `mtl_set_queue_origin_lower_left`, `mtl_set_frame`, `mtl_present`, `mtl_present_wait`,
`mtl_has_window`, `mtl_xv_window_tex`, `mtl_ds_omit`.
The other 49 are statistics, frame-pacing and tuning (`*_stats`, `link_*`, `pkg_*`, `ub*`, `fps_target`, ...): stubs at first.

## nvn_mtl.m (11203 lines, 425 functions): what to write, and what to leave out
The record format is API-neutral: the game's NVN calls become ~45 ops (`OP_SET_RT`, `OP_DRAW`, `OP_BIND_*`, `OP_COPY_*`, ...) in
`nvn_obj.h`, replayed at submit time. A Vulkan replayer implements those ops. The largest pieces in the Metal one are
`draw_` (322 lines), `encode_args_` (236, the argument-buffer fill), `rp_begin_ex_` (199, render pass setup), `mtl_exec` (147),
pipeline building (`pso_*`, ~400), texture upload and deswizzle (`tex_*`, `pkg_upload_`, `up_*`, ~400) and presentation.
A large share is optimisation that has no place in a first version: TBDR pass merging (`fuse_try`, `defer_try`, `hoist_try`),
the geometry-shader mesh emulation, indirect-draw index conversion (`ixc_run`), MetalFX, frame snapshots and capture.

Estimate for a first working Vulkan replayer (menus, then a race): roughly 4-6 thousand lines of C, written against the
`nvn_metal_mapping.md` table, which maps almost one-to-one.

## Order
1. `hle.h` / `dm.h` stand-ins and the Apple replacements above, so `hle_nvn.c` compiles and links (no GPU yet).
2. `nvn_vk.c` with the 33 core entry points (the rest as stubs): pools, addresses, sync, textures from the existing deswizzle code.
3. Op replay: render targets, clears, state, draw, then bindings (the argument fill from the shader reflection).
4. Shaders: SPIR-V from `dmsh_xlate`, reflection from SPIR-V instead of MSL text.
5. Presentation with SDL3.

## Status: hle_nvn.c runs on Linux behind a null GPU
`hle_nvn.c`, `nvn_dirty.c`, `nvn_capture.c`, `nvn_tex.c` and the deswizzle code build and link on Linux (target `nxnvn`; `nvn_link_check`
links every object and fails on any unresolved symbol). Its constructor runs: 537 NVN names, 427 implemented (413 with semantics,
14 empty), the other 110 report in red. What replaced the Apple parts:
- `src/gfx/nvn/nvn_platform.h`: clocks, resident memory from /proc, a safe pointer read, Mach calls that report failure.
- `src/host/sha256.c` for the program keys (tested against FIPS vectors and `sha256sum`), a pointer map instead of CFDictionary.
- `src/gfx/nvn/nvn_null.c`: the 70 Metal-layer functions. Pools and addresses are real, submissions complete at once, nothing is drawn.
- NVN function thunks are svc stubs in the guest window (`nvn_thunk_for`), reaching the implementation through `hle_call`.
- `src/host/faults.c`: the SIGSEGV dispatch dirty tracking needs, re-installed on top of dynarmic's handler after each Jit is made.
Left out for now: `vm_remap` (virtual pools need a shared guest window), LZFSE capture compression, power and QoS statistics.
